## Exact call and fields

The callable remains:

```python
modulo2(score_home, score_away, ball_visible, home_available, away_available,
        dead_score, dead_available, restart_score, restart_available,
        restart_side, half_blocks, config=CONFIG_M2)
```

It returns a fresh Python list of H/A/D/X, one per input frame. It does not mutate
input arrays or blocks. M1 distances, positions and speeds are not decoder inputs;
select the five named M1 fields rather than splatting all seven. No windows or
tag endpoints are accepted as dead/restart truth.

## Half blocks

Canonical blocks are **inclusive `(half, first_frame, last_frame)` triples**,
directly from `games.half_video_blocks(GAME)`:
`[(1,11185,90651), (2,110808,190197)]`. The second graded start is 110808;
its kickoff anchor is not a substitute. Pairs and extra items are rejected,
with no implicit adapter or pair-compatibility mode.

Each half ID must be a positive integer and strictly increase. Boundaries must
be integers, satisfy `0 <= first <= last < n`, and be ordered without overlap.
Boolean values, floats such as `1.0`, strings and malformed blocks are rejected.
NumPy integer scalars are accepted. Either half alone is legal. Adjacent blocks
are legal and still reset **all** state and counters, including restart-side
history. Frames outside supplied blocks are X. Empty blocks give all X; empty
evidence plus empty blocks returns `[]`. A declared block on empty evidence fails.
The runner must separately enforce the full tactical count and frame order.

## Validation and missingness

All ten evidence fields must be regular one-dimensional arrays of equal length.
Lists/tuples and NumPy arrays are supported; scalars, ragged arrays, 2-D arrays
and mismatched lengths raise field-specific `ValueError` before decoding.

- Scores require integer/unsigned/float numeric dtypes, finite values in [0,1].
  Numeric strings, Boolean scores, complex numbers and object-score arrays are
  rejected. Integer scores are safely converted for subtraction; floating
  scores retain their supplied precision. No diagnostic CSV rounding is used.
- Flags accept Boolean values or **only finite numeric 0/1** (including existing
  integer flag sequences). Strings such as `"False"`, NaN, infinity, 2 and
  fractional flags are rejected. There is no truthiness conversion of other data.
- `home_available` and `away_available` each imply `ball_visible`. Every unavailable
  M1/M4 score must be exactly zero. Available scores may legally be zero.
- `restart_available` is independent of `dead_available` and M1 visibility or
  player availability. Sparse-player/ball-only restart evidence remains legal.
- `restart_side` admits exactly H, A or None. A known side with unavailable or
  zero restart evidence is legal and non-decisive. Unknown is never defaulted.

Configuration must be a `ConfigM2`. Counts require positive integers, excluding
Boolean/float/string values. Thresholds require finite real numeric scalars;
control thresholds accept [0,1], dead/restart thresholds (0,1]. Setting a control
threshold to zero explicitly weakens that gate; shipped defaults are positive.
Invalid fields are named in errors. No checks are added for unused distances or
producer position/speed missingness.

## Defaults and rationale

| Setting | Default | Meaning |
|---|---:|---|
| `min_score` | 0.10 | Winning proximity score must be >= this value |
| `min_margin` | 0.05 | Absolute score difference must be **strictly greater** |
| `confirm_frames` | 12 | Consecutive credible control samples for initial acquisition and turnover |
| `dead_min_score` / `restart_min_score` | 0.50 / 0.50 | Minimum available M4 support |
| `dead_confirm_frames` / `restart_confirm_frames` | 3 / 3 | Consecutive supported samples |
| `same_frame_priority` | `"dead"` | Suppress competing restart support on a simultaneous strong-evidence frame |

M1 uses `exp(-distance/tau)`. At its default tau=3 m, score 0.10 corresponds to
about 6.91 m: this declines comparisons between very distant players. The 0.05
absolute margin declines near ties even when both scores are large. Twelve
samples add a short persistence gate against brief proximity flips. At 25 fps
this is nominally 0.48 s, spanning 0.44 s from first to twelfth observation;
three samples are nominally 0.12 s, spanning 0.08 s. Counts are not seconds and
are not automatically rescaled if the runner uses a different frame rate.

Invented checks establish H, then repeat `(1e-9,2e-9)` or `(0.8,0.8000000001)`:
H persists. Actual M1 scores for players 60 m and 59 m away also cannot cause a
turnover. Actual M1 outputs for distances 8 m versus 1 m supply a convincing
opposing sequence and switch once, on sample 12. Initial weak evidence remains X;
initial convincing evidence follows the same 12-sample policy.

These are justified heuristics, not proof of controlled possession or calibrated
probabilities. They were chosen from score semantics and invented cases. No
public labels, desired possession counts or full-match score comparisons were
used. Synthetic tests do not establish match accuracy. Changing M1 tau changes
the distance meaning of these gates and requires an explicit policy review.

## Preserved transition policies

Each block begins X, with no pending control, dead/restart count or side history.
Control comparison requires a visible ball and **both** teams available. A tie,
weak sample, unavailable observation or sample supporting the current team clears
pending opposing confirmation, while retaining the established live team. There
is no backdating: the confirmation frame receives the new label.

D enters after three consecutive strong available dead samples. It persists
through occlusions, strong opposing proximity and long delays, with no expiry,
old-team restoration or tag-endpoint resumption. It leaves only after three
consecutive strong available restart samples. A restart pulse shorter than that
does not release D; a gap clears the pending restart count and accumulated sides.

During restart confirmation, one distinct known H/A side establishes that side;
None samples do not veto a unique known side. No known side, or both H and A,
produces X until control confirms. The restart-confirmation frame may count as
the first credible control sample. A known-side restart bypasses the separate
initial-control confirmation, but normal control processing then applies on that
same frame and subsequent frames. Restart support without active D has no direct
state-transition effect.

Simultaneous strong dead/restart evidence uses the explicit configured priority:
default **dead** suppresses restart that frame; `"restart"` suppresses dead.
The losing signal does not accumulate that frame. The winning signal still needs
its consecutive count. This preserves reviewed behavior and is not the older
plan's proposed retain-state conflict policy. Team adoption of conflict priority,
confirmation lengths and known-side restart trust remains a release decision.
